ワンタップ予定帳(アプリ版)
==========================

ワードをタップするだけで予定を入れられるカレンダーです。
一度開いたあとは、通信なしでも使えます。予定とワードは、使う人の端末の
ブラウザの中にだけ保存されます(ほかの端末や人とは共有されません)。

入っているファイル
------------------
index.html              アプリ本体
manifest.webmanifest    ホーム画面に追加するための設定
sw.js                   通信なしで開くための仕組み(サービスワーカー)
icon-192.png ほか       アイコン(4つ)

配り方(インターネット上に置く)
------------------------------
1. このフォルダの中身を、すべて同じ場所(同じフォルダ)に置きます。
2. https:// で始まるアドレスで開ける場所に公開します。
   GitHub Pages、Cloudflare Pages、Netlify など、静的なファイルを置ける
   サービスなら使えます。
   ※ アプリとして動かすには https:// が必要です(パソコン内の
     localhost だけは例外です)。
3. 使ってもらう人に、そのアドレスを伝えます。
4. 相手は、スマホのブラウザ(AndroidならChrome)でそのアドレスを開き、
   「設定・バックアップ」の「ホーム画面に追加する」、または
   ブラウザのメニューの「ホーム画面に追加」「アプリをインストール」を選びます。
5. 追加したあとは、ホーム画面のアイコンから通信なしで開けます。

自分のパソコンで試すとき
------------------------
このフォルダで次のコマンドを実行し、ブラウザで http://localhost:8000 を開きます。
    python3 -m http.server 8000

生体認証で保護(予定のデータそのものを暗号化)
--------------------------------------------
「設定・バックアップ」の「生体認証で保護」で、予定とワードを暗号化して保存できます。
オンにすると、アプリを開くたびに、指紋・顔、または端末の画面ロックの確認が必要になります。
確認するまで、保存されたデータは読めません。

始め方
1. 回復用のパスワード(8文字以上)を2回入れます。
2. 「生体認証で保護を始める」を押します。確認が2回出ることがあります。
3. 始める前に、バックアップを書き出しておくことをおすすめします。

仕組み
- 予定とワードは、ランダムに作った鍵(AES-256-GCM)で暗号化されます。
- その鍵は、2つの方法で包んで保存されます。
  (1) パスキーから作る鍵(WebAuthnのPRF拡張。指紋・顔・画面ロックで使えます)
  (2) 回復用のパスワードから作る鍵(PBKDF2、600,000回)
  どちらか一方で開けます。パスワードや鍵そのものは保存されません。
- 始める途中で失敗したときは、元の状態に自動で戻ります。
- データが壊れたり、書き換えられたりしていると、読み込めなくなり、
  上書きされずにそのまま残ります。

対応している端末
- パスキーが、PRFという機能に対応している必要があります。AndroidのChromeで、
  Googleパスワードマネージャーにパスキーを保存する場合は、対応しています。
- 対応していない端末では、「始める」を押しても、始まりません(データは変わりません)。
- https:// で開いた場合だけ使えます。

開き方とロック
- 再読み込みしたとき、アプリを開き直したとき、自動ロックのあとは、ロック画面が出ます。
- 指紋・顔・画面ロックが使えないときは、「パスワードで開く」で、回復用のパスワードを入れます。
- 自動ロックは、画面を離してから「すぐ / 1分後 / 5分後」で選べます(初期値は1分後)。
  「すぐ」にすると、ファイルを選ぶ画面などに移っただけでもロックされることがあります。
- 「いますぐロックする」で、手動でロックできます。

やめる・やり直す
- 「保護をやめる」を2回タップすると、暗号化をやめて、元の形で保存します。
- パスキーを入れ替えたいとき、回復用のパスワードを変えたいときは、いったんやめてから、
  もう一度始めてください。
- 保護を始めると、端末のパスワードマネージャーに「ワンタップ予定帳」のパスキーが
  保存されます。使わなくなったら、そこから削除できます。

守れないこと(ご注意ください)
- ロックを解除して使っている間は、画面に予定が表示されます。
- アプリを切り替えたときに出る「最近使ったアプリ」の縮小画面に、内容が写ることがあります。
  気になるときは、自動ロックを「すぐ」にしてください(完全には防げません)。
- 回復用のパスワードを忘れ、さらに指紋・顔でも開けなくなると、予定は誰にも開けません。
  パスワードの控えと、バックアップを用意してください。
- バックアップのファイルは、保護とは別に扱われます。バックアップは、書き出すときに、
  別のパスワードで暗号化できます(下の「バックアップ」を参照)。

バックアップ(大事です)
----------------------
予定とワードは端末の中にだけあります。ブラウザのデータを消したり、端末を
替えたりすると、なくなります。「設定・バックアップ」から、ときどき
バックアップのファイル(.json)を書き出して、別の場所にも保管してください。

パスワードで暗号化
- 書き出すとき、「パスワードで暗号化する」をオンにして、8文字以上のパスワードを
  2回入れます。最初からオンになっています。
- 暗号化したファイルは、パスワードがないと開けません。ファイルの中に、予定の
  言葉は見えません。誰かに見られたり、クラウドに同期されたりしても、
  予定の内容は読まれません。
- パスワードは、このアプリにも、端末にも、保存されません。
  忘れると、バックアップは誰にも(作った人にも)開けません。
  パスワードマネージャーなどに控えておいてください。
- 長くて推測されにくいパスワードほど安全です。誕生日や電話番号、
  よくある言葉は避けてください。
- 暗号化をオフにして書き出すこともできます。その場合、予定の内容が
  そのまま読める形で入るので、ファイルの取り扱いにご注意ください。
- 暗号の方式: PBKDF2(SHA-256、600,000回)で鍵を作り、AES-256-GCMで暗号化します。
  ファイルが書き換えられると、開けなくなります。
- 書き出しや読み込みには、スマホだと数秒かかることがあります。

読み込むとき
- 「バックアップを読み込む」でファイルを選びます。暗号化されたファイルなら、
  パスワードを聞かれます。
- 「追加して読み込む」(おすすめ)か「すべて置き換える」を選べます。
- アドレス(URL)が変わると、データは引き継がれません。引っ越すときも
  バックアップを使ってください。

中身を書き換えて配り直すとき
----------------------------
index.html などを変えたら、sw.js の先頭近くにある VERSION を
(例: 'yotei-v3' → 'yotei-v4')変えてから置き直してください。
変えないと、相手の端末に古いものが残ることがあります。

そのほか
--------
- 文字(Googleフォント)は、初めて通信できる状態で開いたときに端末へ保存されます。
  その間は、Googleのサーバーへ文字を取りに行きます。保存前や取得できないときは、
  端末の標準の日本語フォントで表示されます。
- Googleカレンダーとの自動連携は、この版にはありません。
  CSVの書き出しで、ほかのカレンダーアプリに取り込めます。
